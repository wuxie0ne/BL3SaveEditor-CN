# 游戏名称汉化

应用界面文本使用 WPF ResourceDictionary。游戏数据使用 `BL3SaveEditor/Localization/zh-CN/GameNames.json`：名称表以项目已有英文名称为键，受福效果以游戏内部部件短代码为键。翻译只用于显示；选择框仍绑定原始值，传送点使用资产路径定位，不使用中文名称反查存档。

## 来源和覆盖

名称候选来自本地安装的《无主之地 3》本体、更新和已安装 DLC 的英文及简体中文本地化资源。按本地化命名空间、键和源文本哈希配对，再与项目自带的名称映射按英文原文精确匹配；同一英文对应多个中文结果时不自动选取。英文名称本身可能有不同语境，因此唯一匹配也需要人工校对，不能保证全部与游戏内具体物品一致。

当前表包含 132 个传送点英文名称、1,247 个物品或外观英文名称、98 个前缀和 102 个受福部件效果。部分名称或代码无法可靠对应时保留英文。部件类型标签由内部代码中的明确片段生成，后面的原始代码用于区分相似部件。受福说明中的“（数值）”代表游戏会动态填充的数值，并不是实际百分比；鼠标悬停可查看完整说明和代码。复杂的多段说明未自动合并。

## 更新与校对

`GameNames.json` 的 `travel`、`names` 和 `prefixes` 按英文精确查找；`partEffects` 按部件短代码精确查找，`types`、`partTypes` 和 `guardian` 是人工维护的界面标签。不要把翻译后的值作为存档标识，也不要通过中文名称反向查找资产。添加新项时应确认上下文，无法确认时保留原文。

`scripts/import_game_names.py` 可从已提取的成对英文和中文 `.locres` 文件生成待审候选表。每个 `--pair` 必须来自同一资源和版本；应提供完整的本体、更新及 DLC 配对，否则生成的覆盖范围会缩小。脚本只更新三个名称表，保留现有手工标签和部件效果；它不会提取游戏文件。先输出到临时文件，核对差异后再决定是否替换项目表：

```fish
python3 scripts/import_game_names.py --pair /path/to/en/Game.locres /path/to/zh/Game.locres --output /tmp/game-names-candidate.json
```

校对后运行 `python3 -m unittest discover -s tests -p 'test_game_names.py'`。此检查验证数据键与项目映射的关系，不能替代 Windows 上对界面和存档读写的测试。
